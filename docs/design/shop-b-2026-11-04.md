# Guest shop – approved design B (2026-11-04)

Reference: PROVIDE_Shop_Verbindlicher_Entwurf_B_2026-11-04.png; ChatGPT Library libfile_91e1fb08df148191838f71b42e6f2c34. Exact artwork retained at apps/storefront/public/shop-design/reference-b.png.

User requested the dark shop with compact favorite rows, Beliebt, photo-led menu rows, copper basket and two bottom navigation destinations. The implementation replaces only the guest storefront presentation, on current BS16 storefront source aff32dd. Cart handoff, review, availability, payment safeguards and order status recovery remain connected to the original handlers. Imported carts open the cart, status links and recovered session orders open My Orders. Location address appears in checkout.

Favorites are local to the device, scoped by restaurant and location. Malformed storage is ignored. Asian Kitchen demo Beliebt is an editorial selection (Gyoza, Crispy Duck, Beef Teriyaki, Miso Lachs), not an invented sales ranking; a published Beliebt section takes precedence. Demo photos are extracted byte-for-byte from the existing Asian Kitchen page; other restaurants receive no demo dish photos. No sample menu or pricing is written to the API/database.

The catalog does not expose live open status or preparation estimates. Service controls therefore read Bestellzeiten / Zeit wählen instead of hard-coded Geöffnet / 20–30 Min. The existing test-mode notice remains in cart and orders.

Validation: 110 tests (12 files), TypeScript and full storefront build. Browser checked at 814px reference width and 390px mobile width: favorites save/reload, add/remove cart item with correct totals, detail dialog and focus, categories, cart and empty order navigation. The isolated design-preview harness blocks API mutations and uses explicit sample data. It is not deployed with the shop routes. Comparison screenshot is with identical sample products; actual shop continues to use its real catalog. Responsive layout keeps readable type and usable controls, so small-screen dimensions differ from a uniformly scaled mockup. Minor type/icon differences remain; no pixel-identical claim.
